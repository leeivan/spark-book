# 7.1 本章先看懂什么

&emsp;&emsp;Spark ML Pipeline 的核心链路：特征 -> 模型 -> 评估；训练集/测试集划分与指标选择；如何避免“能跑但不准”的常见问题。

## 一个最小例子

&emsp;&emsp;假设你在做一个会员系统，业务同学想提前识别“下个月可能会流失的用户”。你手里已经有一些基础字段，比如最近 30 天登录次数、投诉次数、套餐类型、是否逾期缴费。最朴素但很有效的做法，就是先把这些字段整理成特征向量，训练一个逻辑回归模型，再用 AUC、Accuracy 之类的指标看看它到底靠不靠谱。

&emsp;&emsp;这个例子故意不追求“最厉害的模型”，而是先把一条完整闭环跑通：准备数据、训练模型、评估效果、调整参数、再次训练。对大多数机器学习项目来说，这条闭环比一开始就追求复杂算法更重要。只要你能把这个最小例子做扎实，后面再接 Pipeline、交叉验证和更复杂的模型时，思路会稳定很多。

&emsp;&emsp;在 Spark 4.x 中，本章的目标不是罗列所有算法名词，而是建立一条可落地的机器学习工作流：准备数据、构造特征、训练模型、评估效果、调节参数并产出可复用的推理流程。书中仍保留部分 `spark.mllib` / RDD 风格示例，用于解释历史 API 与存量系统；如果你是新项目，请优先把注意力放在 `spark.ml`、DataFrame 和 Pipeline 上。
