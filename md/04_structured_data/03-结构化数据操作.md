### 4.3.1 选取列

&emsp;&emsp;表格 4‑2 中的大多数结构化操作，都需要我们显式指定一个或多个列。这里最容易让初学者困惑的点是：有时列可以直接写成字符串，有时又必须写成 `Column` 对象。一个简单判断是，如果只是“按列名引用已有列”，字符串通常就够了；如果要对列做表达式计算、比较、函数调用或别名转换，就应该显式使用 `Column` 类的实例。

&emsp;&emsp;从高层次上看，`Column` 类主要提供以下几类能力：

&emsp;&emsp;（1）数学运算，例如加法，乘法等。

&emsp;&emsp;（2）列值或文字之间的逻辑比较，例如相等、大于、小于等。

&emsp;&emsp;（3）字符串模式匹配。

&emsp;&emsp;有关 `Column` 类中可用的所有功能，请参阅 Scala 文档中的 `org.apache.spark.sql.Column`。理解这一点后，就不难把握使用边界：一旦出现“列表达式”，就应当把列写成 `Column` 实例，而不是普通字符串。为了减少混淆，表格 4‑3 总结了几种最常见的列引用方式。

&emsp;&emsp;表格 4‑3 选取列的可用选项

| 方式     | 例子           | 解释                                     |
| ------ | ------------ | -------------------------------------- |
| ""     | "列名"         | 将一个列引用为字符串类型                           |
| col    | col("列名")    | 通过col函数返回Column类的实例                    |
| column | column("列名") | 与col类似，此函数返回Column类的实例。                |
| $      | $"列名"        | 在Scala中构造Column类的语法糖方式。                |
| '      | '列名          | 通过利用Scala符号文字特征在Scala中构造Column类的语法糖方式。 |

&emsp;&emsp;`col` 和 `column` 函数是同义词，在 Spark 的 Scala 和 Python 函数库中都可用。如果需要经常在 Scala 和 Python 之间切换，使用 `col()` 往往更有可移植性；如果主要使用 Scala，`$"列名"` 或 `'列名` 这样的语法糖会更紧凑。DataFrame 类本身也提供了 `col()` 方法，它在执行两个或多个 DataFrame 联接、需要区分同名列时尤其有用。

```scala
scala> import org.apache.spark.sql.functions._
import org.apache.spark.sql.functions._
scala> val kvDF = Seq((1,2),(2,3)).toDF("key","value")
kvDF: org.apache.spark.sql.DataFrame = [key: int, value: int]
scala> kvDF.columns
res0: Array[String] = Array(key, value)
scala> kvDF.select("key")
res1: org.apache.spark.sql.DataFrame = [key: int]
scala> kvDF.select(col("key"))
res2: org.apache.spark.sql.DataFrame = [key: int]
scala> kvDF.select(column("key"))
res3: org.apache.spark.sql.DataFrame = [key: int]
scala> kvDF.select($"key")
res4: org.apache.spark.sql.DataFrame = [key: int]
scala> kvDF.select('key)
res5: org.apache.spark.sql.DataFrame = [key: int]
```

&emsp;&emsp;也可以直接调用 DataFrame 实例上的 `col()` 方法：

```scala
scala> kvDF.select(kvDF.col("key"))
res6: org.apache.spark.sql.DataFrame = [key: int]
scala> kvDF.select('key, 'key > 1).show
+---+---------+
|key|(key > 1)|
+---+---------+
| 1| false|
| 2| true|
+---+---------+
```

&emsp;&emsp;上面的示例说明了列表达式 `'key > 1` 的特点：一旦不再只是“按列名取列”，而是要做比较、函数调用或运算组合，就应该把列写成 `Column` 对象；如果仍然写成普通字符串，就会触发类型不匹配。在后面的结构化操作示例里，这个边界会反复出现。

### 4.3.2 选择语句（select、selectExpr）

&emsp;&emsp;`select` 和 `selectExpr` 都是在做投影：从 DataFrame 里选出全部列或某个子集，并在需要时顺带完成列变换。两者的主要区别在于表达方式：`select` 更适合已经在 DataFrame API 里写好的列表达式，`selectExpr` 更适合快速写 SQL 风格的表达式、别名和函数调用。

```scala
scala> val df = spark.createDataset(Seq(
| ("Ivan", 1, 2), ("Tom", 3, 4), ("Rose", 3, 5), ("John", 4, 6))
| ).toDF("col1", "col2", "col3")
df: org.apache.spark.sql.DataFrame = [col1: string, col2: int ... 1
more field]
scala> df.show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
| Tom| 3| 4|
|Rose| 3| 5|
|John| 4| 6|
+----+----+----+
```

&emsp;&emsp;上面的代码创建了一个简单的 DataFrame，包含 `col1`、`col2`、`col3` 三列。接下来先看几种最基本的“按列选取”写法：

```scala
scala> df.select("col1").collect
res6: Array[org.apache.spark.sql.Row] = Array([Ivan], [Tom],
[Rose], [John])
scala> df.select($"col1").collect
res7: Array[org.apache.spark.sql.Row] = Array([Ivan], [Tom],
[Rose], [John])
scala> df.select(df.col("col1")).collect
res8: Array[org.apache.spark.sql.Row] = Array([Ivan], [Tom],
[Rose], [John])
```

&emsp;&emsp;如果 `select` 的参数只是字符串列名，就只能表达“按名字取列”；一旦想在选择时直接套用函数或计算表达式，就需要换成 `Column` 对象，例如 `$"col1"`：

```scala
scala> df.select(upper($"col1")).collect
res11: Array[org.apache.spark.sql.Row] = Array([IVAN], [TOM],
[ROSE], [JOHN])
scala> df.select(upper("col1")).collect
<console>:26: error: type mismatch;
found : String("col1")
required: org.apache.spark.sql.Column
df.select(upper("col1")).collect
```

&emsp;&emsp;上面在 `select` 中对字段 `col1` 调用了 `upper()`。这里的关键点不是语法糖本身，而是 `upper()` 需要的输入类型是 `Column`，而不是普通字符串。因此，除了使用 `$"col1"` 这样的写法，也可以改用 `selectExpr()`，把表达式直接写成 SQL 风格字符串：

```scala
scala> df.selectExpr("upper(col1)", "col2 as col22").show
+-----------+-----+
|upper(col1)|col22|
+-----------+-----+
| IVAN| 1|
| TOM| 3|
| ROSE| 3|
| JOHN| 4|
+-----------+-----+
```

&emsp;&emsp;这里的 `selectExpr()` 使用了两个表达式：一个对 `col1` 调用 `upper()`，另一个把 `col2` 改名为 `col22`。它和 `select()` 本质上都在做投影，只是前者接受 SQL 风格表达式，后者更偏向 DataFrame API。实际工程里，如果逻辑已经写在 DataFrame 链式调用里，继续用 `select()` 往往更统一；如果只是想快速表达几个 SQL 风格列变换，`selectExpr()` 会更省力。

```scala
scala> df.select('col1, ('col2 + ('col3 * 2)).as("(col2 + col3 *
2)")).show
+----+-----------------+
|col1|(col2 + col3 * 2)|
+----+-----------------+
|Ivan| 5|
| Tom| 11|
|Rose| 13|
|John| 16|
+----+-----------------+
```

&emsp;&emsp;需要两个列表达式：加和乘，都由Column类中的加函数（+）和乘函数（\*）实现。默认情况下，Spark使用列表达式作为结果列的名称，为了使其更具可读性通常使用as函数将其重命名为更易于理解的列名，我们可能会发现select转换可用于将一个或多个列添加到DataFrame。

### 4.3.3 操作列（withColumn、withColumnRenamed、drop）

&emsp;&emsp;withColumn用于向DataFrame添加新列。它需要两个输入参数：列名和通过列表达式产生的值。如果通过使用selectExpr转换，我们也可以实现几乎相同的目标。但是，如果给定的列名称与现有名称之一匹配，则该列将替换为给定的列表达式。

```scala
scala> df.withColumn("sum", ('col2 + 'col3)).show
+----+----+----+---+
|col1|col2|col3|sum|
+----+----+----+---+
|Ivan| 1| 2| 3|
| Tom| 3| 4| 7|
|Rose| 3| 5| 8|
|John| 4| 6| 10|
+----+----+----+---+
scala> df.withColumn("col2", ('col2 + 'col3)).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 3| 2|
| Tom| 7| 4|
|Rose| 8| 5|
|John| 10| 6|
+----+----+----+
```

&emsp;&emsp;withColumnRenamed转换重命名DataFrame中的现有列名。

```scala
scala> df.withColumnRenamed("col2", "col2_rename").show
+----+-----------+----+
|col1|col2_rename|col3|
+----+-----------+----+
|Ivan| 1| 2|
| Tom| 3| 4|
|Rose| 3| 5|
|John| 4| 6|
+----+-----------+----+
```

&emsp;&emsp;drop转换只是从DataFrame中删除指定的列，可以指定要删除的一个或多个列名，但是只会删除存在的列名，而不会删除那些不存在的列名。可以通过select转换仅投影要保留的列，而删除不需要，但是如果DataFrame有100列，而想删除几列，使用drop转换比select转换更易于使用。

```scala
scala> df.drop('col2).show
+----+----+
|col1|col3|
+----+----+
|Ivan| 2|
| Tom| 4|
|Rose| 5|
|John| 6|
+----+----+
```

### 4.3.4 条件语句（where、filter）

&emsp;&emsp;`where` 和 `filter` 的作用都很直接：只保留满足条件的行。区别主要在表达习惯上，`where` 更接近 SQL 语感，`filter` 更像函数式 API；两者的执行语义是一致的。写条件时，可以使用字符串表达式，也可以使用 `Column` 条件。`filter()` 最常见的几种形式如下：

  - def filter(func: (T) ⇒ Boolean): Dataset\[T\]

  - def filter(conditionExpr: String): Dataset\[T\]

  - def filter(condition: Column): Dataset\[T\]

```scala
scala> df.filter($"col1">"Tom").show
+----+----+----+
|col1|col2|col3|
+----+----+----+
+----+----+----+
scala> df.filter($"col1"==="Tom").show
+----+----+----+
|col1|col2|col3|
+----+----+----+
| Tom| 3| 4|
+----+----+----+
scala> df.filter("col1='Tom'").show
+----+----+----+
|col1|col2|col3|
+----+----+----+
| Tom| 3| 4|
+----+----+----+
scala> df.filter("col2=1").show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
+----+----+----+
scala> df.filter($"col2"===3).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
| Tom| 3| 4|
|Rose| 3| 5|
+----+----+----+
scala> df.filter($"col2"===$"col3"-1).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
| Tom| 3| 4|
+----+----+----+
```

&emsp;&emsp;其中，`===` 是 Column 类中定义的函数，可以判断两列中每行对应的值是否相等；不等于用 `=!=`。`$"col2"` 是语法糖，返回 Column 对象。下面看一看 where 函数：

  - def where(conditionExpr: String): Dataset\[T\]

  - def where(condition: Column): Dataset\[T\]

```scala
scala> df.where("col1 = 'John'").show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|John| 4| 6|
+----+----+----+
scala> df.where($"col2"=!= 3).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
|John| 4| 6|
+----+----+----+
scala> df.where($"col3">col("col2")).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
| Tom| 3| 4|
|Rose| 3| 5|
|John| 4| 6|
+----+----+----+
scala> df.where($"col3">col("col2")+1).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Rose| 3| 5|
|John| 4| 6|
+----+----+----+
```

### 4.3.5 去除重复（distinct、dropDuplicates）

&emsp;&emsp;这两个转换具有相同的行为，但是dropDuplicates允许我们控制使用哪些列应用到重复数据删除逻辑中，如果未指定任何内容，则重复数据删除逻辑将使用DataFrame中的所有列。

```scala
scala> df.select('col2).distinct.show
+----+
|col2|
+----+
| 1|
| 3|
| 4|
+----+
scala> df.dropDuplicates("col2").show()
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
| Tom| 3| 4|
|John| 4| 6|
+----+----+----+
scala> df.distinct.show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|John| 4| 6|
|Rose| 3| 5|
| Tom| 3| 4|
|Ivan| 1| 2|
+----+----+----+
```

### 4.3.6 排序语句（sort、orderBy）

&emsp;&emsp;这两种转换都具有相同的语义，orderBy转换比sort转换更具SQL关系语言的特征。默认情况下排序按升序排列，将其更改为降序很容易。如果指定多个列，每个列的顺序可能不同。

  - def sort(sortExprs: Column\*): Dataset\[T\]

  - def sort(sortCol: String, sortCols: String\*): Dataset\[T\]

  - def orderBy(sortExprs: Column\*): Dataset\[T\]

  - def orderBy(sortCol: String, sortCols: String\*): Dataset\[T\]

```scala
scala> df.sort('col2).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|Ivan| 1| 2|
|Rose| 3| 5|
| Tom| 3| 4|
|John| 4| 6|
+----+----+----+
scala> df.sort('col2.desc).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|John| 4| 6|
| Tom| 3| 4|
|Rose| 3| 5|
|Ivan| 1| 2|
+----+----+----+
scala> df.sort('col2.desc, 'col3.desc).show
+----+----+----+
|col1|col2|col3|
+----+----+----+
|John| 4| 6|
|Rose| 3| 5|
| Tom| 3| 4|
|Ivan| 1| 2|
+----+----+----+
```

### 4.3.7 操作多表（union、join）

&emsp;&emsp;DataFrame 是不可变的，因此“给现有结果追加更多行”的常见做法不是原地修改，而是使用 `union` 生成一张新的结果表。它要求参与合并的两个 DataFrame 具有兼容的 Schema，至少列的数量、顺序和类型需要能够对应起来。

&emsp;&emsp;而在真实业务里，只看单张表往往不够。很多分析都需要把多个数据集按键关联起来，例如把交易表与用户表连接、把订单表与商品维表连接、把事件日志与设备属性连接。`join` 的作用，就是基于某个连接条件把两侧数据按行对齐，并把相关列组合到同一个 DataFrame 中。这样一来，原本分散在不同数据集里的信息就能放到同一个查询或分析流程里处理。本节介绍 Spark SQL 中常见的连接方式及其适用场景。

&emsp;&emsp;执行连接时，通常需要明确两件事：一是连接条件，也就是用哪些列判断两侧哪些行可以匹配；二是连接类型，也就是匹配成功和匹配失败的行分别要不要保留。表格 4‑4 概括了 Spark SQL 中支持的常见连接类型。

&emsp;&emsp;表格 4‑4 Spark SQL中支持的连接类型

| 类型   | 描述                                            |
| ---- | --------------------------------------------- |
| 内连接  | 当连接表达式的值为true时，从两个数据集中返回行。                    |
| 左外连接 | 即使连接表达式的值为false，也从左数据集中返回行。                   |
| 右外连接 | 即使连接表达式的值为false，也从右数据集中返回行。                   |
| 外连接  | 即使连接表达式的值为false，也从两个数据集中返回行。                  |
| 左反连接 | 当连接表达式的值为false时，仅从左侧数据集中返回行。                  |
| 左半连接 | 当连接表达式的值为true时，仅从左侧数据集中返回行。                   |
| 交叉连接 | 通过组合左侧数据集中的每一行与右侧数据集中的每一行来返回行，行数将是每个数据集大小的乘积。 |

  - def union(other: Dataset\[T\]): Dataset\[T\]

  - def join(right: Dataset\[\_\], joinExprs: Column, joinType: String):
&emsp;&emsp;    DataFrame

  - def join(right: Dataset\[\_\], joinExprs: Column): DataFrame

  - def join(right: Dataset\[\_\], usingColumns: Seq\[String\],
&emsp;&emsp;    joinType: String): DataFrame

  - def join(right: Dataset\[\_\], usingColumns: Seq\[String\]):
&emsp;&emsp;    DataFrame

  - def join(right: Dataset\[\_\], usingColumn: String): DataFrame

  - def join(right: Dataset\[\_\]): DataFrame

  - def joinWith\[U\](other: Dataset\[U\], condition: Column):
&emsp;&emsp;    Dataset\[(T, U)\]

  - def joinWith\[U\](other: Dataset\[U\], condition: Column, joinType:
&emsp;&emsp;    String): Dataset\[(T, U)\]

&emsp;&emsp;先定义两个DataFrame：

```scala
scala> val df1 = spark.createDataset(Seq(("Ivan", 1, 2), ("Tom", 3, 4),
("John", 3, 5), ("Tom", 4, 6))).toDF("col1", "col2", "col3")
df1: org.apache.spark.sql.DataFrame = [col1: string, col2: int ... 1
more field]
```

#### 4.3.7.2 内连接

&emsp;&emsp;这是最常用的连接类型，其连接表达式包含在两个数据集中列的相等性比较。仅当连接表达式的计算结果为true时，换句话说当两个数据集中的连接列值相同时，连接的数据集才包含行，列值没有匹配成功的行将从合并的数据集中排除，如果连接表达式使用相等性比较，则连接表中的行数将仅与较小数据集的大小一样大。在Spark
&emsp;&emsp;SQL中，内连接是默认连接类型，因此在连接转换中指定内连接是可选的。

```scala
scala> df1.join(df2, "col1").show
+----+----+----+----+----+
|col1|col2|col3|col2|col4|
+----+----+----+----+----+
|Ivan| 1| 2| 1| 5|
|Ivan| 1| 2| 2| 2|
| Tom| 3| 4| 4| 6|
| Tom| 3| 4| 3| 5|
| Tom| 4| 6| 4| 6|
| Tom| 4| 6| 3| 5|
+----+----+----+----+----+
```

&emsp;&emsp;这里仍然是内连接，但换成了 `joinWith`。它和普通 `join` 的最大区别不在连接条件，而在结果结构：`joinWith` 会把左右两侧对象分别保留在 `_1` 和 `_2` 里，而不是把所有列扁平化到同一个命名空间。

```scala
scala> df1.joinWith(df2, df1("col1") === df2("col1")).show
+----------+----------+
| _1| _2|
+----------+----------+
|[Ivan,1,2]|[Ivan,1,5]|
|[Ivan,1,2]|[Ivan,2,2]|
| [Tom,3,4]| [Tom,4,6]|
| [Tom,3,4]| [Tom,3,5]|
| [Tom,4,6]| [Tom,4,6]|
| [Tom,4,6]| [Tom,3,5]|
+----------+----------+
```

&emsp;&emsp;从结果形态上看，`joinWith` 更像“保留两侧对象结构再做配对”，而普通 `join` 更像“把两侧列拼成一张更宽的表”。如果后续逻辑仍然希望明确区分左右两侧对象，`joinWith` 会更自然。

#### 4.3.7.3 外连接

&emsp;&emsp;是左外连接，此连接类型的连接数据集包括内部联接的所有行，以及连接表达式计算为false的左侧数据集的所有行。对于那些不匹配的行，它将右数据集的列填充NULL值。

```scala
scala> df1.join(df2, df1("col1") === df2("col1"), "left_outer").show

|John| 3| 5|null|null|null|
| Tom| 4| 6| Tom| 4| 6|
| Tom| 4| 6| Tom| 3| 5|
+----+----+----+----+----+----+
```

&emsp;&emsp;是右外连接，此连接类型的行为类似于左外连接类型的行为，只是对右数据集采用了相同的处理。换句话说，连接数据集包括内部连接的所有行以及连接表达式计算为false的右数据集的所有行。对于那些不匹配的行，它将为左侧数据集的列填充NULL值。


### 4.3.8 聚合操作

&emsp;&emsp;聚合操作的核心目的，是把明细数据汇总成更适合分析和决策的结果。常见形式包括：对整张表直接聚合、先按一个或多个列分组再聚合，以及在窗口上做滚动或分段统计。Spark 内置了大量聚合函数，因此很多统计需求都可以直接写成结构化表达式，而不必手工维护中间状态。

&emsp;&emsp;（1）将DataFrame视为一个组。

&emsp;&emsp;（2）通过使用一个或多个列将DataFrame分为多个组，并对每个组执行一个或多个聚合。

&emsp;&emsp;（3）将DataFrame划分为多个窗口，并执行移动平均、累积求和或排名。如果窗口是基于时间的，则可以使用滚动窗口或滑动窗口来完成聚合。

### 4.3.9 用户定义函数

&emsp;&emsp;尽管 Spark SQL 为大多数常见用例提供了大量内置函数，但在某些情况下，现成函数仍不足以表达业务逻辑，这时才需要考虑用户定义函数（User-Defined Functions，UDF）。更稳妥的工程顺序通常是：先尽量使用内置函数和列表达式；只有当逻辑确实无法自然表达时，再引入 UDF。因为一旦进入 UDF，优化器能够直接理解和下推的语义就会减少。

&emsp;&emsp;UDF 可以用 Python、Java 或 Scala 编写，也可以与外部库集成。不过在性能和执行开销上，不同语言实现并不完全等价。

&emsp;&emsp;从概念上讲，UDF 只是“接收输入、返回输出”的普通函数。但从执行角度看，Scala / Java UDF 可以更直接地运行在 JVM 执行器进程中，而 Python UDF 往往需要额外的 Python 进程和序列化开销。因此，在 Spark 作业里使用 Python UDF 时，尤其要关注性能代价。

&emsp;&emsp;使用 UDF 通常包含三个步骤：先编写并测试普通函数；再通过 Spark 的 `udf()` 或注册接口把它包装成可执行函数；最后在 DataFrame 代码或 SQL 查询里调用它。在 SQL 查询中使用 UDF 时，需要先显式注册函数名。
