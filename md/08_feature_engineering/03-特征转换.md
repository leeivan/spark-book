# 8.3 特征转换

特征转换这一节最容易被读成一串互不相关的 API，但在真实项目里，它们通常是连在一起使用的：先把原始文本、类别值或数值列转换成模型可接受的表示，再决定是否需要归一化、分桶、降维或组合特征。理解每个组件“放在链路的哪一段、解决什么问题”，比单独记住它的类名更重要。

### 8.3.1 Tokenizer

Tokenizer 负责把原始文本列切分成词序列，是文本特征流水线里最前面的一个基础步骤。`Tokenizer` 适合做简单按空白分词；如果需要按标点、字符类别或特定模式做更细的切分，通常会改用 `RegexTokenizer`。后者既可以把正则表达式当作分隔符，也可以直接把匹配到的内容当作词元。

```scala
scala> import org.apache.spark.ml.feature.{RegexTokenizer, Tokenizer}
import org.apache.spark.ml.feature.{RegexTokenizer, Tokenizer}
scala> import org.apache.spark.sql.functions._
import org.apache.spark.sql.functions._
scala> val sentenceDataFrame = spark.createDataFrame(Seq(
| (0, "Hi I heard about Spark"),
| (1, "I wish Java could use case classes"),
| (2, "Logistic,regression,models,are,neat")
| )).toDF("id", "sentence")
sentenceDataFrame: org.apache.spark.sql.DataFrame = [id: int, sentence:
string]
scala>
scala> val tokenizer = new
Tokenizer().setInputCol("sentence").setOutputCol("words")
tokenizer: org.apache.spark.ml.feature.Tokenizer = tok_c0f6a3c47f23
scala> val regexTokenizer = new
```

### 8.3.2 StopWordsRemover

停用词移除的目标，是把那些频繁出现但区分度很弱的词先过滤掉，避免它们在后续统计或建模里占据过多权重。`StopWordsRemover` 接收一个字符串数组列作为输入，常常紧跟在 `Tokenizer` 或 `RegexTokenizer` 后面。它既可以使用 Spark 提供的默认停用词表，也可以换成业务自己的词表，并通过 `caseSensitive` 控制是否区分大小写。

```text
id | raw
----|----------
0 | [I, saw, the, red, baloon]
1 | [Mary, had, a, little, lamb]
```

### 8.3.3 n-gram

$n$-gram 是由连续 $n$ 个单词组成的序列，其中 $n$ 是某个正整数。NGram 类可以把输入特征转换成 $n$-gram。它以字符串序列作为输入，参数 $n$ 用于确定每个 $n$-gram 中连续单词的数量，输出则是一个 $n$-gram 序列，其中每个 $n$-gram 都由一个以空格分隔的字符串表示。如果输入序列包含的字符串少于 $n$ 个，则不会生成输出。

```scala
scala> import org.apache.spark.ml.feature.NGram
import org.apache.spark.ml.feature.NGram
scala> val wordDataFrame = spark.createDataFrame(Seq(
| (0, Array("Hi", "I", "heard", "about", "Spark")),
| (1, Array("I", "wish", "Java", "could", "use", "case", "classes")),
| (2, Array("Logistic", "regression", "models", "are", "neat"))
| )).toDF("id", "words")
wordDataFrame: org.apache.spark.sql.DataFrame = [id: int, words:
array<string>]
scala> val ngram = new
NGram().setN(2).setInputCol("words").setOutputCol("ngrams")
ngram: org.apache.spark.ml.feature.NGram = ngram_c2b7dcbc9a97
scala> val ngramDataFrame = ngram.transform(wordDataFrame)
ngramDataFrame: org.apache.spark.sql.DataFrame = [id: int, words:
array<string> ... 1 more field]
scala> ngramDataFrame.select("ngrams").show(false)
+------------------------------------------------------------------+
|ngrams |
+------------------------------------------------------------------+
|[Hi I, I heard, heard about, about Spark] |
|[I wish, wish Java, Java could, could use, use case, case classes]|
|[Logistic regression, regression models, models are, are neat] |
+------------------------------------------------------------------+
```

### 8.3.4 Binarizer

`Binarizer` 会按照阈值把数值特征压成 0/1 特征。它适合那些业务上只关心“是否超过某个门槛”的场景，例如是否高于风险阈值、是否达到某个曝光量级。输入列既可以是单个数值列，也可以是向量列；大于阈值的值会被映射成 `1.0`，其余映射成 `0.0`。

```scala
scala> import org.apache.spark.ml.feature.Binarizer
import org.apache.spark.ml.feature.Binarizer
scala> val data = Array((0, 0.1), (1, 0.8), (2, 0.2))
data: Array[(Int, Double)] = Array((0,0.1), (1,0.8), (2,0.2))
scala> val dataFrame = spark.createDataFrame(data).toDF("id",
"feature")
dataFrame: org.apache.spark.sql.DataFrame = [id: int, feature: double]
scala> val binarizer: Binarizer = new
Binarizer().setInputCol("feature").setOutputCol("binarized_feature").setThreshold(0.5)
binarizer: org.apache.spark.ml.feature.Binarizer =
binarizer_ecd8c65d1d28
scala> val binarizedDataFrame = binarizer.transform(dataFrame)
binarizedDataFrame: org.apache.spark.sql.DataFrame = [id: int, feature:
double ... 1 more field]
scala> println(s"Binarizer output with Threshold =
${binarizer.getThreshold}")
Binarizer output with Threshold = 0.5
scala> binarizedDataFrame.show()
+---+-------+-----------------+
| id|feature|binarized_feature|
+---+-------+-----------------+
| 0| 0.1| 0.0|
| 1| 0.8| 1.0|
| 2| 0.2| 0.0|
+---+-------+-----------------+
```

### 8.3.5 PCA（主成分分析）

`PCA` 用来做线性降维。它会把原本可能相关的多个特征，投影到一组新的正交方向上，并尽量保留数据中最主要的变化信息。对高维稠密特征来说，这通常有助于压缩维度、降低噪声，或者为后续模型提供更紧凑的输入表示。先看一个把 5 维向量投影成 3 维主成分的最小示例。

### 8.3.6 PolynomialExpansion

`PolynomialExpansion` 会把原始特征展开到更高阶的多项式空间，从而显式引入平方项、交叉项和更高次项。它常见于线性模型想要拟合非线性关系、但又不希望直接换成更复杂模型的场景。例如，当 `degree = 2` 时，二维输入 $(x, y)$ 会被展开成包含 $x^2$、$xy$、$y^2$ 在内的更高维表示。下面用一个 3 阶展开的最小示例来观察结果。

### 8.3.7 Discrete Cosine Transform（DCT）

`DCT` 会把一段实值序列从时域投影到频域表示。对特征工程来说，更值得记住的是它的用途：当原始特征本身带有顺序结构或频率结构时，DCT 可以把它们转换成另一组更适合压缩、去噪或频域分析的系数表示。Spark 这里实现的是 DCT-II 变换。


### 8.3.8 StringIndexer

`StringIndexer` 用来把字符串标签列转换成数值索引列。这通常是类别特征进入 `OneHotEncoder`、树模型或分类器之前的第一步。默认情况下，它会按标签出现频率排序，把最常见的标签映射为 0；如果需要，也可以改用下面几种排序策略：

1.  frequencyDesc：按标签频率的降序（最频繁的标签分配为0）

2.  frequencyAsc：按标签频率的升序（最不频繁的标签分配为0）

3.  alphabetDesc：按字母顺序的降序

4.  alphabetAsc：按字母顺序的升序

默认选项是 `frequencyDesc`。对于训练阶段没见过的新标签，可以通过 `handleInvalid` 选择报错、跳过，或者把它们统一放进额外的桶里。如果输入列本身是数字，Spark 也会先把它当作字符串标签来建立索引。真正需要记住的是：`StringIndexer` 的输出列通常不是最终特征，而是后续编码器或模型的输入。

先看一个最小输入示例，DataFrame 只包含 `id` 和 `category` 两列：

```text
id | category
----|----------
0 | a
1 | b
2 | c
3 | a
4 | a
5 | c
```

代码 8‑17

在这个例子里，`category` 一共有三个取值：`a`、`b`、`c`。把它映射成 `categoryIndex` 后，会得到下面的结果：

```text
id | category | categoryIndex
----|----------|---------------
0 | a | 0.0
1 | b | 2.0
2 | c | 1.0
3 | a | 0.0
4 | a | 0.0
5 | c | 1.0
```

代码 8‑18

这里 `a` 被映射成 0，是因为它最常见；`c` 次之，因此是 1；`b` 最少，所以是 2。除此之外，还要关心一个工程上很常见的问题：如果线上数据里出现训练时没见过的标签，该怎么处理？`StringIndexer` 提供了三种常见策略：

  - 直接报错，这是默认行为。

  - 跳过包含未知标签的整行记录。

  - 把未知标签统一放进一个额外桶里，例如索引 `numLabels`。

沿用前面的 `StringIndexer`，这次让它去处理一个包含新标签的数据集：

### 8.3.9 IndexToString

`IndexToString` 与 `StringIndexer` 正好相反，它会把数值索引列还原成原始字符串标签。最常见的场景是：先用 `StringIndexer` 把标签转成索引训练模型，再在预测输出阶段用 `IndexToString` 把预测索引还原成更可读的标签名称。沿用前面的例子，当前 DataFrame 包含 `id` 和 `categoryIndex`：

```text
id | categoryIndex
----|---------------
0 | 0.0
1 | 2.0
2 | 1.0
3 | 0.0
4 | 0.0
5 | 1.0
```

#### 工程补充：TargetEncoder

当类别取值非常多时，`OneHotEncoder` 很容易让特征空间迅速膨胀：维度变高了，训练和存储成本也会跟着上升。这类场景下，Spark 4.x 里的 `TargetEncoder` 更值得额外关注。它不再把每个类别展开成独立位置，而是利用目标列的统计信息，把类别映射成一个更紧凑的数值表示。对高基数类别特征来说，这通常比无脑做独热编码更省维度，也更接近真实项目里的建模方式。

不过，`TargetEncoder` 的代价是更容易引入标签泄漏风险。它必须只在训练数据上拟合，再把同样的映射规则应用到验证集、测试集和线上推理数据；如果把全量数据一起编码，再回头做评估，得到的效果往往会被高估。因此，它更适合作为“高基数类别的工程补充方案”，而不是替代所有类别编码方法的默认主线。

换句话说，类别特征并不存在放之四海而皆准的一种编码方式。低到中等基数的类别，继续沿着 `StringIndexer + OneHotEncoder` 这条链路通常最直接；一旦类别数量开始膨胀，再考虑 `TargetEncoder` 这类更紧凑的方案，会更符合真实项目里的成本约束。带着这条分界线，再看后面的 `VectorIndexer`，就更容易理解它解决的是另一类问题：向量里哪些维度应该被当成离散类别，而不是如何展开原始字符串标签。

补充说明：范数描述的是“向量有多大”。在特征工程里，最常见的用途不是做纯数学推导，而是决定样本在归一化之后保留怎样的尺度信息。不同范数对应不同的“大小”定义，因此会影响归一化结果。

在 $n$ 维实向量空间 $\mathbb{R}^{n}$ 中，向量 $\mathbf{x} = (x_{1}, x_{2}, \ldots, x_{n})$ 的长度通常由欧几里得范数给出，那么：

$$ \lVert x \rVert_{2} = \left( {x_{1}}^{2} + {x_{2}}^{2} + \cdots + {x_{n}}^{2} \right)^{\frac{1}{2}} $$

公式 8‑6

上面的公式给出的是向量 $x$ 的欧几里得范数；如果把它应用到差向量 $x-y$ 上，就得到常见的欧几里得距离 $\lVert x - y \rVert_{2}$ 。更一般地，对于实数 $p \geq 1$ ，向量的 $p$-范数可以写成：

$$ \lVert x \rVert_{p} = \left( |x_{1}|^{p} + |x_{2}|^{p} + \cdots + |x_{n}|^{p} \right)^{\frac{1}{p}} $$

公式 8‑7

当 $p$ 取 1、2、 $\infty$ 时，会得到几种最常见的形式：

$L^{1}$ 范数的定义如下：

$$ \lVert x \rVert_{1} = \sum_{i} |x_{i}| $$

公式 8‑8

它表示向量各分量绝对值之和。把它应用到两个向量的差上，就得到常见的绝对误差和：

$$ SAD(x_{1},x_{2}) = \sum_{i}^{}|x_{1i} - x_{2i}| $$

公式 8‑9

在优化问题里，$L^{1}$ 正则化常被用来鼓励稀疏解，因此很多特征选择方法也会借助它的这一性质。

$L^{2}$ 范数是最常见的一种范数：

$$ \lVert x \rVert_{2} = \sqrt{\sum_{i} x_{i}^{2}} $$

公式 8‑11

它表示向量元素平方和再开平方。类似地，把它作用到两个向量的差上，可以得到平方差和：

$$ SSD(x_{1},x_{2}) = \sum_{i}^{}{(x_{1i} - x_{2i})^{2}} $$

公式 8‑12

在机器学习里，$L^{2}$ 范数常用于正则化，帮助抑制过大的参数并降低过拟合风险。

当 $p = \infty$ 时，得到的是 $\infty$-范数，它衡量的是向量中绝对值最大的那个分量：

$$ \lVert x \rVert_{\infty} = \max_{i} |x_{i}|,\quad x = (x_{1}, x_{2}, \cdots, x_{n}) $$

公式 8‑14

通常会把它简写成：

$$ \lVert x \rVert_{\infty} = \max_{i} |x_{i}| $$

### 8.3.14 StandardScaler

很多模型对特征尺度非常敏感。如果某些列的数值范围远大于其他列，它们就可能在距离计算、梯度更新或正则化过程中占据不成比例的影响。StandardScaler 的作用，就是按列统计均值与标准差，再把向量特征缩放到“单位标准差”或“零均值 + 单位标准差”的尺度上。

`StandardScaler` 是一个估算器（Estimator）：它会先在训练数据上拟合，得到 `StandardScalerModel`，再把同样的缩放规则应用到训练集、验证集或测试集上。两个最常见的参数是：

withStd：默认为 `true`，把各特征缩放到单位标准偏差。

withMean：默认为 `false`，在缩放前先做中心化。这会把稀疏向量转成稠密向量，因此在高维稀疏特征上要谨慎使用。

### 8.3.15 MinMaxScaler 

`MinMaxScaler` 会按列把特征重新缩放到给定区间，最常见的是 $[0,1]$ 。它适合需要保留相对大小关系、同时又希望不同列落在统一量纲上的场景。最常见的两个参数是：

min：0.0为默认值，转换后的下限，由所有特征共享。

max：1.0为默认值，转换后的上限，由所有特征共享。

`MinMaxScaler` 会先在训练数据上计算每一列的最小值和最大值，得到 `MinMaxScalerModel`，再用同一套缩放规则去转换数据。

$$ Rescaled(e_{i}) = \frac{e_{i} - E_{\min}}{E_{\max} - E_{\min}} \cdot (max - min) + min $$

公式 8‑17

当 $E_{\max} = E_{\min}$ 时， $Rescaled(e_{i}) = 0.5 \cdot (max + min)$ 。这意味着原本为零的分量也可能被映射成非零值，因此即使输入是稀疏向量，输出也会变成 `DenseVector`。下面这组 Scala REPL 示例会加载 `libsvm` 格式的数据集，并把每个特征重新调整到 $[0,1]$ 。

### 8.3.17 Bucketizer 

`Bucketizer` 用来把连续数值切成离散区间，也就是常说的分箱。它适合那些“业务上更关心数值落在哪个区间，而不是精确值本身”的场景，例如年龄段、价格档位、风险等级等。这个转换最关键的参数就是 `splits`：

`splits` 给出的是各桶边界。如果有 $n+1$ 个边界，就会得到 $n$ 个桶。边界必须严格递增；如果希望覆盖所有可能的数值，通常应该显式把 `Double.NegativeInfinity` 和 `Double.PositiveInfinity` 放在两端。

如果你无法事先保证输入值一定落在有限区间内，把正负无穷作为首尾边界通常更稳妥。下面演示如何把一列双精度特征映射成桶索引。

### 8.3.18 ElementwiseProduct 

`ElementwiseProduct` 会把输入向量和一个给定的权重向量逐元素相乘。可以把它理解成“对向量的每一维乘上一个固定系数”，因此很适合做手工权重调整、规则加权，或者把业务先验快速编码进特征里。

$$\begin{pmatrix}
v_{1} \\
 \vdots \\
v_{N} \\
\end{pmatrix} \circ \begin{pmatrix}
w_{1} \\
 \vdots \\
w_{N} \\
\end{pmatrix} = \begin{pmatrix}
v_{1}w_{1} \\
 \vdots \\
v_{N}w_{N} \\
\end{pmatrix}$$

### 8.3.21 QuantileDiscretizer 

`QuantileDiscretizer` 也做分箱，但它不是手工指定边界，而是根据数据分布按分位数自动切桶。这样得到的桶往往更均衡，特别适合长尾分布或你不容易手动设置合理边界的连续特征。桶的数量由 `numBuckets` 指定，但实际得到的桶数可能更少，因为不同输入值的个数未必足够支撑这么多不同分位点。

关于缺失值，还需要留意 `NaN` 的处理方式。拟合分位点时，`NaN` 不会参与正常分箱；在转换阶段，可以通过 `handleInvalid` 选择报错、跳过，或者把 `NaN` 单独放进一个特殊桶中。

分箱边界默认通过近似分位数算法计算，精度可由 `relativeError` 控制；如果设为 0，则会转向更精确、但代价更高的计算方式。最终边界会自动向 `-Infinity` 和 `+Infinity` 延展，以覆盖输入值范围。这里继续用一个只包含 `id` 和 `hour` 两列的 DataFrame 做演示：

```text

----|------
0 | 18.0
----|------
1 | 19.0
----|------
2 | 8.0
----|------
3 | 5.0
----|------
4 | 2.2
```
